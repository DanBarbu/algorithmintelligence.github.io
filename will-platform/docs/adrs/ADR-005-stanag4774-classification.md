# ADR-005 — STANAG 4774 as the Canonical Classification Metadata Standard

**Status:** Accepted  
**Date:** 2026-01-15  
**Authors:** @will-compliance-officer, @will-tech-lead  
**Reviewers:** @will-security-engineer, @will-product-owner

---

## Context

WILL handles data at multiple classification levels (UNCLASSIFIED → NATO SECRET) and must interoperate with Romanian national classified systems (Law 182/2002 + HG 585/2002) and NATO FMN Spiral 4/5 infrastructure. Classification metadata must travel with every track, command, and audit log — not just at rest.

## Decision

Adopt **STANAG 4774** (Confidentiality Metadata Label Syntax) as the canonical in-flight classification standard, with **STANAG 4778** crypto-binding deferred to Sprint 9.

Implementation:
- Every `TrackEvent` proto carries a `label_xml TEXT` field containing a STANAG 4774 XML label.
- The `classification_level` PostgreSQL enum (`UNCLASSIFIED`, `NATO_RESTRICTED`, `NATO_CONFIDENTIAL`, `NATO_SECRET`) is the fast-path index; `label_xml` is the authoritative value.
- The audit service validates that `label_xml` classification level matches `classification_level` on every write.
- Sprint 0–8: labels are generated by the ingestion service. Sprint 9+: labels are crypto-bound per STANAG 4778 using Vault-managed signing keys.

## Consequences

- **Positive:** Full alignment with NATO data-centric security model and FMN Spiral 4 requirements.
- **Positive:** Romanian MApN and SRI interoperability: both accept STANAG 4774 labels.
- **Negative:** XML label adds ~200–400 bytes per track event. Acceptable at 10k sensor/s (< 4 MB/s overhead).
- **Sprint 0 scope:** `label_xml` column exists but is nullable; label generation is a no-op stub returning `UNCLASSIFIED` XML. Full implementation in Sprint 9.
